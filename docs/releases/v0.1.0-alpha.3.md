# v0.1.0-alpha.3

Selected-player recording now follows movement with easing instead of rigidly
centering the champion. The camera retains the chosen player and normal elevated
angle; it does not switch to other fights or reproduce the original player's
mouse input.

The recorder computes a damped horizontal offset and sends short linear Replay
API keyframes, letting the client interpolate between frames. Each update is
confirmed through native camera readback before another update is sent. Identity,
camera height, viewing angle, and FPS input controls remain verified. Axis locks
are explicitly disabled because native tests showed that they freeze the camera
in world space despite retaining a selected target.

TDD regressions cover moving targets, ignored keyframe updates, delayed readback,
target disappearance during acknowledgment, camera drift, and ignored FPS
control settings. CI runs Windows Go 1.26/stable tests plus portable race and
vulnerability checks. Native camera probes applied 239 fractional offset changes
across two capture segments without endpoint mismatch.

One exact-source Windows FULL recording then passed on patch 16.20.824.8524,
windowed 1280×720/requested 30 FPS: replay 498.412384 seconds, WebM 498.406656
seconds, video packets 0.037000–498.318000 seconds. Full decoding, camera/target
checks through death and respawn, and owned-process cleanup passed. Start,
combat, death, and victory frames were inspected. Native output is variable-rate.

This remains an experimental Windows amd64 release. Other patches, maps, capture
profiles, and observer-archive playback are unverified. The recorder still takes
a compatible local `.rofl`; login, replay acquisition, and uploads belong to the
calling application. No dependencies were added.
