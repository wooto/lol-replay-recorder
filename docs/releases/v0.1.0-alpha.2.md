# Native Windows recording fixes

Fixes native replay recording that could lose the target camera, start video five
seconds late, or report a full result because audio retained the requested length
after video ended early.

```sh
go get github.com/wooto/lol-replay-recorder@v0.1.0-alpha.2
```

- Adds `Config.LaunchReplay` and `ReplayProcess` for caller-owned client launch;
  the core retains process identity checks and closes only the owned game.
- Selects through Replay API with verified keyboard fallback. Persistent target,
  elevated offset, and rotation tracks preserve the view through encoder seeks
  and respawns; unknown camera/death state fails.
- Uses real-time capture and an empirically verified five-second native pre-roll
  on patch 16.20. Completion sentinels still require camera and output validation.
- Fully decodes video and checks first/final video packet timestamps. Audio length
  cannot hide a short video. Packet metadata and decoding errors use bounded memory.
- Covers launch hooks, HTTP behavior, ignored settings, death/respawn, clock and
  completion behavior, and short video with focused TDD regressions.

**Live validation:** one KR local replay passed on Windows amd64 in windowed
1280×720 with requested 30 FPS. Replay: 498.412 seconds; WebM: 498.304 seconds;
video packets: 0.035–498.276 seconds. Start, combat, death, and victory frames were
inspected; full video decoding and owned-process cleanup passed. Windows Go 1.26
and stable CI, portable race checks, vet, formatting, and vulnerability scans pass.

**Experimental:** the negative pre-roll is observed client behavior, not a Riot
compatibility guarantee. Other patches/maps/profiles, direct executable launch on
the tested installation, and observer-archive playback remain unverified. Native
real-time WebM is variable-rate. Riot login, replay downloads, and uploads belong
to the calling application; no OP.GG or LCU dependency is added to the core.
